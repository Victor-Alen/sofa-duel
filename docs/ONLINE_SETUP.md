# 沙发只能坐一个 - 在线对战使用说明

## 🎮 在线对战功能

游戏现在支持真正的在线多人对战！两个玩家可以通过互联网实时对战，**无需任何后端配置**。

### 技术实现

- **WebRTC (PeerJS)**: 点对点直连，延迟极低
- **免费信令服务器**: PeerJS 协助双方建立连接
- **无需注册**: 不需要 Firebase 或其他后端服务
- **即开即用**: 创建房间后立即可以游玩

## 使用方法

### 创建房间（房主）

1. 打开游戏：https://victor-alen.github.io/sofa-duel/
2. 点击 **"联网对战"** 模式
3. 点击 **"创建房间"**
4. 复制显示的 6 位房间号（如：`ABC123`）
5. 将房间号分享给朋友

### 加入房间（玩家 2）

1. 打开游戏：https://victor-alen.github.io/sofa-duel/
2. 点击 **"联网对战"** 模式
3. 点击 **"加入房间"**
4. 输入 6 位房间号
5. 点击 **"加入房间"**

### 选择角色

1. 两个玩家都加入后，会弹出角色选择对话框
2. 各自点击选择喜欢的角色，再点击 **“准备好”**
3. 准备后角色会锁定；如需更换，先取消准备
4. 双方都准备后自动开始游戏；重选角色时双方需要重新准备

### 游戏控制

#### 移动端
- **左侧摇杆**: 移动角色
- **右侧按钮**: 释放技能

#### PC 端
- 双方都可用 **WASD 或方向键**移动
- 按 **空格**释放自己角色的技能

## 游戏流程

```
创建/加入房间 → 等待对手 → 双方选角并准备 → 自动开局 → 分出胜负 → 再来一局 / 重选并重新准备 / 离开房间
```

## 注意事项

### 网络要求
- 两个玩家都需要稳定的互联网连接
- 首次连接可能需要 5-10 秒
- 如果连接失败，请按页面提示检查房间号或切换网络后重试
- 严格 NAT 或限制 WebRTC 的网络可能无法直连，建议双方改用其他网络

### 房间规则
- 每个房间最多 2 人
- 房间在房主离开后自动关闭
- 建议通过微信/QQ 分享房间号

### 性能优化
- 游戏状态每 50ms 同步一次（20Hz）
- 输入状态约每 33ms 同步一次（约 30Hz），技能按下立即发送
- 手机联机显示完整场地，并使用与房主一致的运动边界
- WebRTC 直连确保低延迟；实际延迟仍取决于双方网络与 NAT 环境

## 故障排除

### 无法创建房间
- 检查网络连接
- 刷新页面重试
- 房间号可能已被占用，稍后重试

### 无法加入房间
- 确认 6 位房间号正确（不区分大小写）
- 确认房主尚未离开房间
- 检查网络连接

### 游戏卡顿
- 检查网络延迟
- 尝试靠近路由器
- 关闭其他占用带宽的应用

### 断线重连
- 对手意外掉线（如刷新页面、网络闪断）时，房间会保留 **20 秒**等待重连，选角界面会提示“对手已断开，等待重连…”
- **房主刷新页面也会恢复房间**：房主重新打开游戏后自动回到同一房间号（对手自动重连即可），不再一脚踢散整局
- 掉线一方重新打开游戏后，输入**同一房间号**即可回到选角界面，双方重新选角并准备后继续，房主无需重建房间
- **关于第三设备观战**：评估后暂不做——两座位安全守卫（拒绝第三连接）是对局防劫持的核心设计，观战需要引入座位以外的只读连接与转发链路，复杂度高于其派对场景价值；想看 AI 对决可用首页的「自动演示」
- 20 秒内未重连，房间自动关闭；对局中途掉线的比赛作废，重连后重新选角开局

## 技术细节

### PeerJS WebRTC
- 使用 PeerJS 库实现 WebRTC 连接
- 免费信令服务器：`0.peerjs.com`
- STUN 服务器：小米、QQ、哔哩哔哩与 Google 公共 STUN 并行备用

### 数据同步
- **房主 (Player 1)**: 负责发送完整游戏状态（20Hz）
- **客户端 (Player 2)**: 发送输入状态（约 30Hz），接收游戏状态并进行本地预测
- 每轮选角和每局游戏都有独立编号，过期选角、输入、开局与快照消息会被丢弃

### 安全性
- 所有数据点对点传输
- 不经过中央服务器（除信令外）
- 房间号随机生成，难以猜测
